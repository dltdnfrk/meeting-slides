# Meeting Slides 시운전 시나리오

이 문서는 Meeting Slides의 현재 구현을 기준으로 최초 실행, 녹음, 전사, PPT 생성, 히스토리, 재실행 및 삭제 동작을 확인하기 위한 시운전 절차다.

## 핵심 확인 항목

- 최초 실행 시 과거 회의 화면이 자동으로 복원되지 않는다.
- 녹음 중 전사가 계속 누적된다.
- PPT 생성 중에도 녹음과 전사가 유지된다.
- 생성된 PPTX 파일이 실제로 열린다.
- 히스토리를 삭제하면 재실행 후에도 다시 나타나지 않는다.

---

## 1. 앱 최초 실행

### 조작

1. Meeting Slides 앱을 실행한다.
2. 브라우저가 열릴 때까지 기다린다.

### 정상 결과

- 중앙 제목이 `새 회의 준비`로 표시된다.
- 중앙에 이전 회의 슬라이드가 아닌 초기 안내 화면이 표시된다.
- 오른쪽 전사 문장 수가 `0`이다.
- 과거 회의는 왼쪽 히스토리에만 표시된다.
- 어떤 히스토리도 자동으로 선택되지 않는다.
- 지난 전사와 저장 경로가 자동으로 표시되지 않는다.

> 과거 기록 자체를 지우는 동작은 아니다. 히스토리는 보존하되 현재 작업면만 초기화된다.

---

## 2. 로컬 서비스 연결 확인

### 정상 결과

브라우저와 로컬 Bun 앱 서버가 연결되면 내부 연결 상태가 `connected`가 된다.

### 서버가 종료된 경우

다음 문구가 표시된다.

```text
앱 서버 연결이 끊겼습니다. 다시 연결하는 중…
```

이 상태는 Whisper 모델이나 인터넷 연결이 아니라 다음 로컬 연결을 의미한다.

```text
브라우저 ↔ 로컬 Bun 앱 서버
```

Whisper 실행에 실패한 경우에는 `녹음 시작 실패`와 같은 별도 오류가 표시되어야 한다.

---

## 3. 참석자 등록

### 조작

1. 상단의 `참석자` 버튼을 누른다.
2. 참석자 이름을 입력한다.
3. 저장한다.

### 정상 결과

- 상단에 참석자 수가 반영된다.
- 녹음 중에는 참석자 구성이 잠긴다.
- 등록한 참석자를 바탕으로 화자 정보를 확인할 수 있다.

> 참석자 등록은 선택 사항이지만 화자 구분을 확인하려면 녹음 전에 등록하는 것이 좋다.

---

## 4. 녹음 시작

### 조작

1. `녹음 시작`을 누른다.
2. macOS가 마이크 권한을 요청하면 허용한다.
3. 실제로 몇 문장을 말한다.

### 정상 결과

- 버튼이 `녹음 중지`로 변경된다.
- 하단 상태 영역에 녹음 시간과 전사 문장 수가 표시된다.
- 오른쪽 전사 영역에 문장이 순서대로 추가된다.
- 화자가 구분되면 `화자 1`, `화자 2` 등이 표시된다.
- 왼쪽 히스토리에 현재 회의가 `진행 중`으로 표시된다.

### 현재 생성 방식

안정성을 위해 발언할 때마다 PPT를 자동 생성하지 않는다. 녹음 중 중앙 화면이 안내 상태로 유지되는 것은 정상이다.

---

## 5. 녹음 중 PPT 생성

### 조작

1. 전사가 충분히 쌓일 때까지 말한다.
2. 하단의 `슬라이드 초안 만들기` 버튼을 누른다.

### 정상 흐름

1. 버튼을 누른 순간까지 누적된 전사가 스냅샷으로 고정된다.
2. LLM이 장표 구조를 생성한다.
3. Scene Graph 기반 PPTX가 생성된다.
4. 완료 상태와 슬라이드 수가 표시된다.
5. 저장 결과가 산출물 라벨로 표시된다.

예상 표시:

```text
슬라이드 5장 완성
PowerPoint 저장 완료
```

> AI 구성 실패(예: Codex 사용량 한도) 시에는 `기본 형식으로 N장 완성`으로 표시되고, 잡음 없이 정리된 폴백 덱이 생성된다.

### 생성 중 정상 동작

- 녹음은 계속된다.
- 새로운 전사가 오른쪽에 계속 추가된다.
- 녹음 버튼은 비활성화되지 않는다.
- 버튼을 누른 뒤 추가된 발언은 이미 생성 중인 PPT에 섞이지 않는다.

### 생성 완료 미리보기 동작

생성 완료 시 필름스트립과 중앙 화면에 생성된 장표가 즉시 표시된다. 중앙 화면에서 다른 장표를 확인할 수 있고, 안내 바를 누르면 실시간/원본 화면으로 돌아간다.

---

## 6. 추가 전사를 포함해 다시 생성

### 조작

1. 첫 번째 PPT 생성 후 회의를 계속한다.
2. 새로운 내용을 추가로 말한다.
3. `슬라이드 초안 만들기`를 다시 누른다.

### 정상 결과

- 두 번째 버튼 클릭 시점까지 누적된 전체 전사로 새 PPT가 생성된다.
- 이전 PPT 파일은 보존된다.
- 새로운 export 폴더에 별도 저장된다.

---

## 7. 녹음 종료

### 조작

1. 상단의 `중지`를 누른다.
2. 종료 처리가 완료될 때까지 기다린다.

### 정상 결과

- 버튼이 다시 `녹음 시작`으로 변경된다.
- 왼쪽 히스토리 상태가 `진행 중`에서 `종료`로 변경된다.
- 전사와 생성 결과가 해당 회의 기록에 연결된다.
- 로컬 앱 서버는 계속 실행된다.

---

## 8. 히스토리 다시 열기

### 조작

왼쪽 히스토리에서 종료된 회의를 클릭한다.

### 정상 결과

- 해당 회의 제목이 표시된다.
- 저장된 전사가 표시된다.
- 컴파일 기록이 있으면 `만든 슬라이드 N장`이 표시된다.
- 현재 녹음 작업과 과거 회의 선택 상태가 구분된다.

새로고침하거나 앱을 다시 열면 빈 작업면으로 시작한다. 과거 회의를 보려면 히스토리에서 직접 선택해야 한다.

---

## 9. 히스토리 삭제

### 조작

1. 삭제할 회의 오른쪽의 휴지통 버튼을 누른다.
2. 확인창에서 삭제를 승인한다.

### 정상 결과

- 해당 회의가 목록에서 사라진다.
- DB의 전사, 슬라이드, 참석자 및 컴파일 기록도 함께 삭제된다.
- 선택 중인 회의를 삭제하면 중앙 화면이 빈 작업면으로 복귀한다.
- 이미 내보낸 PPTX, PDF 등의 파일은 유지된다.
- 현재 녹음 중인 회의는 삭제할 수 없다.

---

## 10. 앱 재실행

### 조작

1. 앱을 완전히 종료한다.
2. 앱을 다시 실행한다.

### 정상 결과

- 과거 회의가 자동으로 열리지 않는다.
- 중앙 제목이 `새 회의 준비`이다.
- 전사 문장 수가 `0`이다.
- 히스토리 목록만 보존된다.
- 삭제했던 회의는 다시 나타나지 않는다.

---

## 이상 동작 보고 양식

구현과 다른 동작이 발생하면 다음 형식으로 기록한다.

```text
단계:
조작:
기대 결과:
실제 결과:
화면에 표시된 문구:
재현 빈도:
```

예시:

```text
단계: 5. 녹음 중 PPT 생성
조작: 전사 8문장 뒤 슬라이드 초안 만들기 클릭
기대 결과: 녹음 유지 및 PPTX 저장
실제 결과: 버튼이 비활성화되고 저장 결과가 표시되지 않음
화면에 표시된 문구: 슬라이드 초안을 만드는 중…
재현 빈도: 2회 중 2회
```
